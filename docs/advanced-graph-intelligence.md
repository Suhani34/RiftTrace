# RiftTrace Advanced Graph Intelligence

## Purpose

The Path Intelligence component extends RiftTrace security-aware
propagation with explainable analysis of modeled propagation routes.

It answers questions such as:

- Which modeled paths connect a specified compromise to critical assets?
- Are there multiple alternative paths?
- Which intermediate assets occur across many paths?
- Which relationships occur across many critical paths?
- Which modeled relationship may be useful to evaluate through the
  counterfactual control engine?

## Security-Aware Paths

Path Intelligence does not construct paths from raw network
connectivity.

It consumes successful transitions generated by the existing
security-aware propagation model.

Therefore path generation remains subject to modeled conditions such
as:

- source privilege;
- authentication requirements;
- MFA requirements;
- vulnerability exploitability;
- vulnerability attack vector;
- vulnerability privilege requirements.

Connectivity alone does not imply exploitability.

## Path Enumeration

RiftTrace enumerates bounded simple paths.

The default limits are:

- maximum depth: 8 transitions;
- maximum paths: 1000.

The limits prevent combinatorial graph growth from creating
unbounded processing requirements.

When the configured maximum number of paths is reached, the result is
marked as bounded/truncated.

## Critical Paths

A path may be classified as critical when its target asset has
CRITICAL asset criticality.

A path may also be classified as business-critical when its target
supports a critical modeled business process.

These classifications describe the modeled environment and are not
predictions of actual business loss.

## Node Chokepoints

An intermediate asset is considered a path chokepoint candidate when
it appears across multiple analyzed paths.

Path coverage is calculated as:

paths containing node / total analyzed paths

The starting asset and final target asset are excluded from
intermediate-node chokepoint calculations to avoid trivial results.

## Relationship Chokepoints

Relationship coverage is calculated as:

paths containing relationship / total analyzed paths

A relationship with 100% coverage appears on every analyzed path in
the bounded path set.

This does not prove that modifying the relationship is the optimal
real-world security action.

## Defensive Leverage

Path Intelligence reports how many currently enumerated paths contain
a node or relationship.

This quantity is used as an explainable candidate-selection metric.

Actual modeled remediation effectiveness should be evaluated using
the RiftTrace counterfactual and security-control simulation engines.

## Interpretation

RiftTrace paths are potential modeled propagation routes.

They do not represent observed attacker activity, guaranteed
compromise sequences, or predictions of exact attacker behavior.
